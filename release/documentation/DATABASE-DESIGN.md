# Database Design

SQLite 3 via `sqlite-jdbc 3.45.1.0`. Schema in `src/main/resources/schema.sql`, applied idempotently by `SchemaInitializer` (`CREATE ... IF NOT EXISTS`, `schema_version` table). Pragmas: `foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout=5000`.

## 1. Entity-relationship summary

```
users            (auth only, no FKs)
employees 1 ──── 0..1 drivers
vehicles  1 ──── *   vehicle_assignments * ──── 1 drivers
vehicles  1 ──── *   trips               * ──── 1 drivers
vehicles  1 ──── *   maintenance_records  1 ── 0..1 expenses
vehicles  1 ──── *   fuel_records         1 ── 0..1 expenses
vehicles  0..1 ─ *   expenses
audit_logs, code_sequences, app_settings, schema_version   (support tables)
```

## 2. Tables

| Table | Purpose | Notable constraints |
|---|---|---|
| `users` | Accounts | `username` UNIQUE, `email` UNIQUE, `role` CHECK in 4 roles, `password_salt`/`password_hash` (PBKDF2), lockout columns, `must_change_password` |
| `employees` | Staff | `employee_code` UNIQUE, `email` UNIQUE (case-insensitive index), `status` CHECK, `deleted_at` for recycle bin |
| `drivers` | Driver profile | `employee_id` UNIQUE FK → employees (one profile per employee), `licence_number` UNIQUE, `licence_category` CHECK A–E |
| `vehicles` | Fleet | `vehicle_code` UNIQUE, `registration_number` UNIQUE, `vin` UNIQUE (nullable), `vehicle_type` CHECK, `status` CHECK in 6 states, `year BETWEEN 1900 AND 2100`, `current_mileage >= 0` |
| `vehicle_assignments` | Who holds which vehicle | FKs to vehicles & drivers; **partial unique indexes** `uq_assignment_active_vehicle` and `uq_assignment_active_driver` (`WHERE status='ACTIVE'`) make double assignment impossible at DB level |
| `trips` | Journeys | `trip_code` UNIQUE, `status` CHECK, CHECK `end_mileage IS NULL OR end_mileage >= start_mileage` |
| `maintenance_records` | Service/repair | FK vehicle, `type`/`status` CHECK, `cost >= 0` |
| `fuel_records` | Purchases | FK vehicle, optional FK driver, `quantity_litres > 0`, `total_cost` |
| `expenses` | All costs | optional FK vehicle, `category` CHECK, `amount > 0`, `source_fuel_record_id` / `source_maintenance_record_id` UNIQUE nullable FKs (ON DELETE CASCADE) |
| `audit_logs` | Trail | timestamp, username, action, module, reference, description |
| `code_sequences` | EMP-/DRV-/VEH-/TRP-/MIG- counters | `prefix` PK |
| `app_settings` | Key/value (demo-loaded flag, migration markers) | `key` PK |
| `schema_version` | Migration bookkeeping | |

Every business table has `id INTEGER PRIMARY KEY AUTOINCREMENT`, `created_at`, `updated_at`; employees/drivers/vehicles additionally have `deleted_at` (soft delete). 36 idempotent CREATE statements in total (13 tables, 23 indexes).

## 3. Integrity mechanisms

* **Foreign keys** with `ON DELETE RESTRICT` (default) for history tables — a vehicle with trips cannot be hard-deleted (service also blocks it with a friendly message).
* **CHECK constraints** mirror the enums, so bad data cannot arrive through any path.
* **Unique indexes** enforce codes, plates, licences, e-mails and active-assignment exclusivity.
* **Transactions** wrap every multi-row operation (see ARCHITECTURE §3).
* **Prepared statements only** — `JdbcSupport` never concatenates user input into SQL.

## 4. Sample queries used by the dashboard

```sql
SELECT status, COUNT(*) FROM vehicles WHERE deleted_at IS NULL GROUP BY status;
SELECT strftime('%Y-%m', expense_date), SUM(amount) FROM expenses
 WHERE expense_date BETWEEN ? AND ? GROUP BY 1 ORDER BY 1;
SELECT COALESCE(SUM(end_mileage - start_mileage),0) FROM trips
 WHERE status='COMPLETED' AND date(return_time) BETWEEN ? AND ?;
```

## 5. Migration from legacy storage

`LegacyDataMigrator` reads `~/FemzykVehicleSystem/users.dat` and `profiles/<user>/fleet-data.dat` (Java serialization from v4.x) through whitelisted shadow classes and inserts users (same PBKDF2 hash → same password works, role FLEET_MANAGER, forced password change) and vehicles (placeholder plates `MIG-0001…`, renter kept in notes, recycled ones land in the recycle bin). Markers in `app_settings` make it idempotent; original files are never modified. Verified by `LegacyDataMigratorTest` using files generated by the **original** v4 classes.
